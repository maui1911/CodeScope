Component spec

Errors & toasts

Five surfaces for surfacing async outcome & failure: toast, inline helper, banner, terminal error, blocker. Each has a clear when; never use two for the same event. Handoff for Claude Code.
01 · When to use what

Pick the surface from the impact, not the severity

Severity (info / ok / warn / err) is a style dimension. Surface (toast / banner / inline / terminal / blocker) is a scope dimension. They're independent — you can have a green toast or a red banner. Use this matrix to pick the surface.

Event Surface When · why
Async action finished toast Worktree spawned · session committed · clipboard copied. Out-of-flow confirmation; user moved on. Auto-dismiss 4s.
Form field invalid inline Validation belongs under the field that caused it. Never as a toast — the user can't tie it back to a control.
Workspace-level state issue banner Repo behind origin · model API key invalid · update available. Persistent header bar — sticks until resolved or dismissed.
Tool call / agent failure terminal Inline in the session log where the failure happened — full stack + suggested fix + retry. Never lifts out into a toast.
App can't start / data corrupt blocker Catastrophic, recovery requires user action. Full-window. Always shows error code + “Copy diagnostics”.
Background sync conflict toast + banner Toast at the moment of the conflict, banner persists until resolved. Two surfaces, but one event — tag with the same id so the toast click opens the banner detail.
02 · Toast anatomy

The toast primitive

Bottom-right anchored stack. 380px wide. 6 slots: accent rail · icon · title · message · actions · close. Optional progress meter for long-running.

Worktree spawned
feat/export-pdf is checked out and a Claude session is warm.
1Severity rail 2px left bar. The only structural color cue — accent (info), green (ok), amber (warn), red (err).
2Severity icon 24×24 tile, 12×12 line glyph. Tinted bg matches rail. Optional when stack shares severity.
3Title 13px Inter 600. Past-tense outcome — “Spawned”, not “Spawning”. Max 1 line.
4Message 12px · #A0A0A0. Fills in scope/context. Inline code for refs. Max 2 lines.
5Actions Max 2: primary (accent border) and ghost. Primary maps to a noun-verb (Open, Undo, Retry).
6Close Always present. Hover-fades to 0.6 opacity. Click cancels auto-dismiss.
7Auto-dismiss meter 2px progress strip. Drains in 4s (info/ok), 8s (warn), persists (err). Pauses on hover.

04 · Stack & behavior

Multiple toasts at once

Bottom-right · 28px from window edge · 10px gap. Newest on top. Cap at 3 visible; older toasts fold under with reduced scale + opacity. A “+N more” chip surfaces if more queue up. Hovering any toast in the stack pauses dismiss for all of them.

Context near cap
Branch pushed
feat/reporting → origin · 3 commits.
Worktree spawned
feat/export-pdf · session warm.
Stack rules
  • Newest = bottom (front-of-stack), most prominent
  • Older toasts fold under with scale(0.97), then scale(0.94)
  • Cap at 3 visible; stash overflow behind a “+N more” chip
  • Hover anywhere = pause every meter in the stack
  • Errors never fold — they stay full-size until dismissed
  • De-dupe by id — same id replaces, doesn't add

06 · Terminal errors

Inline in the session log

When a tool call or shell command fails, the error renders in the terminal stream — not as a toast. This keeps cause and effect adjacent and preserves scrollback.

Tool call failed ENOENT · exit 1 · 04:12.7s
$ pnpm --filter @cs/api run test:integration
↳ Error: Cannot find module '@cs/db/migrations/20240412_add_export.sql'
at Migrator.load (packages/db/src/migrator.ts:48:11)
at async runIntegration (apps/api/test/integration.ts:12:3)
at async node:internal/main/run_main_module:23:47
Likely cause: the migration file was deleted in git pull 4m ago and a worktree still references it. Try pnpm install or restart the dev server.

Anatomy. head (severity bar + title + meta code) → body (command, error line, stack) → optional hint (Claude's diagnosis) → actions. The hint row is what makes this a CodeScope error, not a stock terminal one.

07 · Blocker

The catastrophic full-window state

Reserved for can't continue: corrupt project file, missing license, version-mismatch with daemon. Always shows an error code (for support) and a copyable diagnostics blob. No nav chrome, no sidebar.

09 · Build notes

Rules that aren't obvious from the pixels

Title is the outcome, message is the why Title: past-tense, factual — “Branch pushed,” “Push failed.” Message: scope and reason. If you can't say the title in 5 words, the surface is wrong (probably a banner or terminal error).
Errors never auto-dismiss Info/ok/warn drain on a meter. Errors stay until clicked away. Don't skip the meter for non-errors — it's how the user judges “is this safe to ignore?”.
Actions are noun-verbs of the toast “Branch pushed” → Open PR. “Worktree spawned” → Open. Never generic “OK” or “Got it.” If there's no obvious action, omit them — close handles it.
Validation is inline, never toast A toast for “name required” is the worst kind of error UX — the user can't tie it back to the input. Every field has its own error slot. Toasts confirm submission outcomes, not validation.
De-dupe aggressively Pass an id with every toast. Same id within 5s = replace, don't stack. The 4th “Saved.” in 200ms is a bug, not a feature.
Banners are sticky, not modal They share row with the workspace, never block. If something must block, it's a dialog or blocker — never a banner.
Terminal errors include a hint The dashed-divider hint row (Claude's diagnosis) is what differentiates this from a stock terminal. Always include — empty if Claude has nothing to say (rare).
Blocker shows the code & copy button Every blocker has an error code and a “Copy diagnostics” button. The diagnostics blob includes app version, OS, project state file path, and the last 50 log lines. Don't make support guess.
10 · Implementation

Suggested API

// One imperative API for toasts. Banner / blocker are components, not imperative.

type Severity = "info" | "ok" | "warn" | "err";

type ToastAction = {
  label: string;
  intent?: "primary" | "ghost" | "danger";
  onClick(): void | Promise<void>;     // resolves before dismiss
};

type ToastInput = {
  id?: string;                          // for de-dupe + replace
  severity: Severity;
  title: string;                         // past tense, ≤ 1 line
  message?: ReactNode;
  actions?: ToastAction[];               // max 2
  duration?: number | "persistent";     // override default
  icon?: ReactNode;                       // override severity icon
};

// Helpers wrap toast() so callers don't carry severity:
toast.info(input)    // 4s
toast.ok(input)      // 4s
toast.warn(input)    // 8s
toast.err(input)     // persistent, no meter

// Inline error — colocate with field. Don't ship a "FieldError" component;
// expose the helper slot on your form primitives so it's harder to misuse:

<Field
  label="Worktree name"
  value={name}
  onChange={setName}
  error={nameError}            // string | null — drives ring + helper
  warn={nameWarn}             // optional, lower priority than error
/>

// Banner — workspace-scoped state. Imperative + declarative:

useBanner("repo-behind", {
  severity: "warn",
  title: "Repo is 14 commits behind origin/main",
  message: …,
  actions: [{ label: "Pull now", onClick: pullMain }],
  while: state.commitsBehind > 0,    // auto-clear when false
});

// Terminal error — emit through the same stream as stdout:

session.emit({
  kind: "tool-error",
  command: "pnpm test:integration",
  exitCode: 1, durationMs: 4127,
  message: "Cannot find module '@cs/db/migrations/…'",
  stack: […], hint: "Likely cause: …",
  actions: ["retry", "pnpm install", "copy", "ask-claude"],
});

// Blocker — single global slot. Setting it replaces the entire window UI.
setBlocker({
  code: "E_STATE_VERSION_MISMATCH",
  title: "CodeScope can't open this project",
  message: …,
  diagnostics: () => collectDiagnostics(),
});
