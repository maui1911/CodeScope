Component spec

Dialog system

One Dialog primitive, five recurring flavors: Confirm, Destructive, Info, Form, and Choice. Every dialog in CodeScope should compose from these parts — don't build bespoke modals. Handoff for Claude Code.
01 · Anatomy

The dialog primitive

Every dialog is the same 7 slots: scrim, icon, eyebrow, title, close, body, footer. Width picked from the w-sm / w-md / w-lg / w-xl scale (420 / 480 / 560 / 640). Height grows to fit content; there is no fixed height.

04 · Build notes

Rules that aren't obvious from the pixels

One primitive, five flavors Never branch on visual structure — branch on flavor (confirm | destructive | info | form | choice). The primitive picks icon, eyebrow color, primary-button style, dismiss behavior.
Buttons always right-aligned Order: ghost cancel → primary. Destructive replaces primary with the red button but keeps the position — muscle memory never moves.
Title is a question, body is context Write titles as the user's question to themselves (“Delete worktree?”), not a system noun (“Deletion”). Body fills in consequences and scope, never restates the title.
Destructive defaults are strict No close icon · no scrim-click dismiss · ↵ doesn't auto-confirm · typed-name confirmation for project-level deletes. Red only for destructive — never for “save,” “submit,” “error”.
Keyboard map ⎋ cancel (unless strict) · ↵ primary (unless destructive) · ⌘↵ submit from anywhere in a form · Tab trap inside dialog · focus returns to the trigger on close.
Stacking Max one dialog at a time. Opening a second dismisses the first. For wizards, use the same dialog and swap body — don't stack.
Loading + error inside the dialog When the primary action is async: disable buttons, show a spinner on the primary, freeze the body. On error, shake ±4px (200ms) and surface a red helper under the offending field — never a second dialog.
Mobile / narrow Below 520px viewport, dialogs pin to bottom and span full width (radius 12px top corners only, 0 bottom). Footer buttons stack, primary on top.
05 · Implementation

Suggested component shape

// Single primitive. Flavor drives visual + behavioral defaults.

type DialogFlavor = "confirm" | "destructive" | "info" | "form" | "choice";
type DialogSize   = "sm" | "md" | "lg" | "xl";

type DialogButton = {
  label: string;
  intent?: "primary" | "destructive" | "ghost" | "secondary";
  kbd?: string;                 // e.g. "↵" or "⌘↵"
  loading?: boolean;
  disabled?: boolean;
  onClick(): void | Promise<void>;
};

type DialogProps = {
  open: boolean;
  flavor: DialogFlavor;
  size?: DialogSize;               // default md
  eyebrow?: string;                // e.g. "Confirm", "Destructive"
  title: string;                   // phrased as a question
  icon?: ReactNode;                 // override the flavor icon
  body: ReactNode;

  buttons: DialogButton[];          // right-aligned, max 2
  keyboardHint?: string;           // left-side meta text

  strict?: boolean;                 // true on destructive — no ⎋/scrim
  requireTypedConfirm?: string;    // e.g. "PestScope"

  onDismiss?(): void;
};

// Convenience wrappers — build in terms of the primitive:
function ConfirmDialog(p: …)     { /* flavor=confirm */ }
function DestructiveDialog(p: …) { /* flavor=destructive, strict=true */ }
function InfoDialog(p: …)        { /* flavor=info, auto-dismiss 6s */ }
function FormDialog(p: …)        { /* flavor=form, ⌘↵ submits */ }
function ChoiceDialog(p: …)      { /* flavor=choice, ↑↓ + ↵ */ }
